I am happy to announce another certification for Full Stack Open: Relational Databases, with TypeScript, Express, PostgreSQL and Sequelize ORM and JWT for authentication.

At a high-level, it is an API written using Express that allows for full CRUD operations on a database with Users, Blogs, user reading list of blogs, and login sessions. Each of these is an individual table and has its own endpoint. Many of the dangerous operations are guarded on authentication, which is managed by a user session.  

I really enjoyed this course. I had been wanting to dig into database beyond MySQL query syntax for a while and this was a great opportunity. Before working on this I thought of myself as a developer with a predilection towards the front-end. By the end of this I didn't miss having a that front-end and felt quite comfortable with my tests giving me constant feedback.   

Some highlights: 
- realizing that the application was growing beyond my ability to conceptualize without types and progressively migrating to TypeScript. I was grateful for the flexibility that TypeScript offered in this sense. I am overall very happy that I did this because it offered me the opportunity to improve my TypeScript and discover some very cool features. One that got me especially excited was function generics:

![func-gen-1](./assets/function-generic-1.png)

I would say that I am generally very pro-typing, since it helps me reason about contracts without having to review the entire implementation, though I still appreciate the ability to script quickly without that.

- I made the decision pretty early on to do things test-first using TDD. While this definitely slowed down the process, it gave me a lot more confidence in what I was building; building things incrementally by hypothesizing about the feature implementation, and then going red-green-etc. I often think about what Kent Beck says about TDD, when he says that he used to experience so much anxiety about correctness and when he started using this approach, it all went away.  
- One thing that surprised me: I was very familiar with writing complex SQL read queries from my time at the Classic Learning Test. I did not anticipate the learning curve on using Sequelize as an ORM; needing to translate my thinking about table and field relationships (especially associations) into the Sequelize model. This was an opportunity to get more familiar with the source code of a large open-source project. I even had to write a custom-script using @jridgewell/trace-mapping to map some of the sequelize errors onto the compiled code using the source-map. I can't say I wasn't intimidated at first, but I feel more confident now if I run into an error that is buried deep inside a dependency library.
