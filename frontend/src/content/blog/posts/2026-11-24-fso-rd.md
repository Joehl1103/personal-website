I am happy to announce another certification for [Full Stack Open: Relational Databases](https://fullstackopen.com/en/part13), with TypeScript, Express, PostgreSQL and Sequelize ORM and JWT for authentication.

At a high-level, it is an API written using Express that allows for full [CRUD operations](https://en.wikipedia.org/wiki/Create,_read,_update_and_delete) on a database with Users, Blogs, user reading list of blogs, and login sessions. Each of these is an individual table and has its own endpoint. Many of the dangerous operations are guarded on authentication, which is managed by a user session.

I really enjoyed this course. I had been wanting to dig into database beyond MySQL query syntax for a while and this was a great opportunity. Before working on this I thought of myself as a developer with a predilection towards the front-end. By the end of this I didn't miss having a that front-end and felt quite comfortable with my tests giving me constant feedback.

Some highlights:
- realizing that the application was growing beyond my ability to conceptualize without types and progressively migrating to TypeScript. I was grateful for the flexibility that TypeScript offered in this sense. I am overall very happy that I did this because it offered me the opportunity to improve my TypeScript and discover some very useful features of its type-system. One that got me especially excited was [generic functions](https://www.typescriptlang.org/docs/handbook/2/functions.html#generic-functions):

I would say that I am generally very pro-typing, since it helps me reason about contracts without having to review the entire implementation.

- I made the decision early on to use [Test-Driven-Development](https://en.wikipedia.org/wiki/Test-driven_development). While this slowed down the process, it gave me a lot more confidence in what I was building; building things incrementally by hypothesizing about the feature implementation, and then going red-green-etc. I often think about what Kent Beck says regarding TDD, that he used to experience so much anxiety about correctness, but when he started using this approach, it all went away.

- **One thing that surprised me**: I was very familiar with writing complex SQL read queries from my time at the Classic Learning Test. I did not anticipate the learning curve on using [Sequelize](https://sequelize.org) as an ORM ([Object Relational Mapping](https://en.wikipedia.org/wiki/Object%E2%80%93relational_mapping)) tool; and especially needing to translate my thinking about table and field relationships (especially associations) into the Sequelize model. There are many times where it would have been much easier to write the raw SQL query. That said, this was an opportunity to get more familiar with the source code of a large open-source project. I even had to write [<i class="fa-brands fa-github"></i> a custom-script](https://github.com/Joehl1103/fso-13-psql-app/blob/master/scripts/map-error.mjs) using [<i class="fa-brands fa-github"></i> @jridgewell/trace-mapping](https://github.com/jridgewell/trace-mapping) to map some of the sequelize errors onto the compiled code using the source-map. I can't say I wasn't intimidated at first, but I feel more confident now if I run into an error that is buried deep inside a dependency library.

**Next steps**: using this newfound confidence to build out a backend for my personal website to store comments on blog posts!

If you are interested in taking a look at the source code ([<i class="fa-brands fa-github"></i> repo link](https://github.com/Joehl1103/fso-13-psql-app)), I welcome any feedback!
